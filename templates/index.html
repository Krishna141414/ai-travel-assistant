    05 - honest notes

    Limitations

    • The model is tiny (Qwen2.5-0.5B on CPU): replies take a few seconds each, and it sometimes picks bad args - that is why validation, retry and the fallback router exist.
    • Hotels are sample data (20 fictional hotels in Indian cities); bookings are a local JSON file, no real payments.
    • The fallback router uses simple keywords + regex, so it only understands plainly worded requests.
    • Successful answers are written by the small model and can word things loosely; the result card always shows the exact tool output. Errors use a fixed template, because in testing the model once described a rejected booking as "confirmed".
    • Cached currency rates are approximate and only used (and labelled) when the live API fails.
